Настройте набор войск и выбор целей для своей ИИ-личности.

Добавьте нужные поля в AIC-конфигурацию. Без новых настроек существующие личности сохраняют своё поведение.

### Цели атаки

| `AttackTargetPolicy` | Выбор цели |
| --- | --- |
| `Inherit` (по умолчанию) | По существующему `TargetChoice`. |
| `LowestPopulation` | Противник с наименьшим числом мирных жителей. |
| `FewestTroops` | Противник с наименьшим числом военных единиц. |
| `LowestCombatPower` | Наименьшая оценочная военная сила, без учёта расстояния. |
| `Random` | Случайный допустимый противник, с равными шансами для всех. |
| `LastAggressor` | Последний нападавший, чья атака отвечает условиям для ответного удара. |

`AttackTargetCommitment` определяет, как долго сохранять выбранного противника:

- `Default`: для новых правил — `PerAttack`; с `Inherit` — прежнее поведение.
- `PerAttack`: выбрать цель в начале атаки и не менять до её завершения.
- `UntilDefeated`: сохранять противника между атаками, пока он остаётся допустимой целью.

Случайный противник для каждой атаки; тот же противник может выпасть снова:

```json
{
  "AttackTargetPolicy": "Random",
  "AttackTargetCommitment": "Default"
}
```

### Набор войск

По умолчанию `RecruitPolicy` равен `Native`. Выберите `WeightedRoles`, чтобы распределять набор между обороной, набегами, основной атакующей армией и вылазками из замка. Списки войск, интервалы и квоты сохраняются.

Для **каждого** уровня силы (`Default`, `Weak`, `Strong`) четыре целочисленных веса должны давать в сумме **100**. `RecruitProbSortie…` по умолчанию равен 0. Веса управляют набором, но не гарантируют итоговые пропорции армии.

Пример: больше обороны при слабом ИИ; приоритет обороне, пока она не укомплектована:

```json
{
  "RecruitPolicy": "WeightedRoles",
  "RecruitProbDefDefault": 30,
  "RecruitProbRaidDefault": 20,
  "RecruitProbAttackDefault": 40,
  "RecruitProbSortieDefault": 10,
  "RecruitProbDefWeak": 60,
  "RecruitProbRaidWeak": 10,
  "RecruitProbAttackWeak": 20,
  "RecruitProbSortieWeak": 10,
  "RecruitProbDefStrong": 20,
  "RecruitProbRaidStrong": 20,
  "RecruitProbAttackStrong": 50,
  "RecruitProbSortieStrong": 10,
  "RecruitConditions": [
    {
      "When": {
        "DefenseIncomplete": true
      },
      "Defense": 60, "Raid": 0, "Attack": 30, "Sortie": 10
    }
  ]
}
```

`RecruitConditions` необязателен (по умолчанию: `[]`, максимум восемь правил). Первое подходящее правило заменяет веса текущего уровня силы. Каждое правило требует всех четырёх весов с суммой 100.

В `When` задайте уровень силы через `Strength` или используйте условия:

| Условие | Проверяет, что… |
| --- | --- |
| `HomeUnderThreat` | База под угрозой. |
| `AttackActive` | Идёт атака. |
| `DefenseIncomplete` | Оборона ещё не укомплектована. |
| `EquipmentSurplus` | Есть избыток снаряжения. |

`true` требует выполнения условия, `false` — его отсутствия. Должны совпасть все указанные условия. Пропущенные условия не учитываются; пустой `When` подходит всегда.

### Изменение настроек

Применяйте связанные поля вместе. Частичное обновление сохраняет пропущенные значения; для отмены прежнего `UntilDefeated` задайте `Default`. Возврат обеих систем к прежнему поведению:

```json
{
  "RecruitPolicy": "Native",
  "AttackTargetPolicy": "Inherit",
  "AttackTargetCommitment": "Default"
}
```

Прежние веса вылазок и правила сохраняются при `Native`, но не действуют; не включайте их в это обновление. Нулевой вес вылазок при `WeightedRoles` не возвращает `Native`.
