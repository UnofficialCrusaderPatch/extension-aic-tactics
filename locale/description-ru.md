AIC Tactics позволяет настраивать набор войск, атаки, набеги и осадные машины для каждого установленного ИИ. Укажите параметры в его AIC. Новые правила набора, атак и набегов включаются по желанию; пропущенные поля осады используют настройки модуля. Списки и лимиты войск остаются в силе.

### Набор войск

- `RecruitProbSortieDefault`, `RecruitProbSortieWeak`, `RecruitProbSortieStrong`: доля вылазок для каждого уровня силы. Если задать любую из них, этот ИИ использует четыре доли набора. Оборона, набеги, атака и вылазки должны давать 100 для каждого уровня.
- `RecruitConditions`: другие доли для конкретной ситуации. Например, при угрозе замку: 70% оборона, 20% атака, 10% вылазки. При каждом наборе применяется первое подходящее правило.
- `RecruitPolicy`: необязательный переключатель совместимости. `Native` сохраняет исходный выбор; `WeightedRoles` явно включает четыре доли.
- `DefRecruitComposition`: `PreserveSlots` соблюдает пропорции `DefUnit1..8`; `Native` сохраняет обычный выбор.
- `RecruitInitialDefenseMonths`: сколько времени набеги и основная армия ждут заполнения оборонного лимита. 0 отключает ожидание; по умолчанию 6 месяцев.

Доля вылазок автоматически включает `WeightedRoles`. Для правил ситуации, состава обороны и `RecruitInitialDefenseMonths` его нужно указать явно. Интервалы и лимиты набора продолжают действовать.

### Атаки и ответные действия

- `AttackTargetPolicy`: `Inherit` использует `TargetChoice`. `LowestPopulation`, `FewestTroops`, `LowestCombatPower`, `Random` и `LastAggressor` выбирают одного противника на каждую атаку.
- `AttackTargetCommitment`: старые AIC могут пользоваться этим полем. В новых выбор цели и срок задаются вместе в `AttackTargetPolicy`, например `{ "Choice": "LastAggressor", "UntilDefeated": true }`.
- `AttackPreparation`: `DuringAttack` готовит следующую волну дома, пока армия атакует; `Native` сохраняет прежний порядок.
- `AttackActivation`: `AfterProvocation` ждёт достаточно серьёзного нападения врага перед атакой или набегом; `Immediate` не ждёт. Оборонительные вылазки остаются доступными.
- `ProvocationRules`: остаётся для старых AIC, `AfterProvocation` и угрозы при наборе. В новых AIC пороги для `LastAggressor` можно задать внутри `AttackTargetPolicy.Provocation`.

### Набеги

- `RaidTargetPolicy`: `Native` сохраняет обычные набеги; `NearestReachable` выбирает близкие доступные здания; `Opportunistic` учитывает предпочтения и опасность; `RandomNearby` выбирает доступное здание случайно, затем атакует соседние.
- `RaidGroupCount` (1–4) делит имеющиеся силы; `RaidMinGroupSize` (1–256) заставляет малые отряды ждать или объединяться.
- `RaidFocus` принимает `Any`, `Food`, `Industry`, `HighValue` или доли, например `{ "Food": 60, "Industry": 20 }`; остаток подходит для любых зданий. Работает с `Opportunistic` и `RandomNearby`. `RaidRiskTolerance` задаёт риск; `RaidEnemyScope` — выбор врага.

Пять параметров после `RaidTargetPolicy` требуют новой политики набегов. `RaidUnitsBase`, `RaidUnitsRandom`, `RaidUnit1..8` и `RaidRetargetDelay` продолжают действовать.

### Осада и инженеры

- `SafeSiegePlacement` избегает занятых мест строительства (модуль: ВКЛ).
- `ActualSiegeResourcePayment` требует материалы и золото; недостающее ИИ покупает обычной торговлей (ВЫКЛ).
- `CoordinatedSiegeHarassment` отправляет собранную группу машин к доступным огневым позициям (ВЫКЛ). `SiegeHarassMinEngines` задаёт желательный минимум (0–20, обычно 3); `HarassingSiegeEnginesMax` по-прежнему ограничивает общее число.
- `LargerSiegeForces` повторяет набор машин, пока есть живые свободные инженеры атаки и допустимые места (ВЫКЛ). `SiegeForceMax` — необязательный предел (0–64); при 0 число определяют инженеры. `AttMaxEngineers` ограничивает расчёты.

Безопасное размещение включается автоматически вместе с расширенными осадными функциями. Учёт ролей инженеров включён по умолчанию; Fixed Engineers отвечает за расчёты и оборудование.

Явные параметры осады в AIC имеют приоритет над настройками модуля.
