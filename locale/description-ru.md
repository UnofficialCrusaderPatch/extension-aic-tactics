AIC Tactics разрабатывается, чтобы авторы ИИ-персонажей могли по желанию настраивать правила найма войск, атак и набегов.

Планируются вероятности найма и вылазок, зависящие от обстановки, подготовка следующей армии во время атаки, выбор противников и ответные удары, а также разделение сил для набегов на ограниченное число групп. Существующие ИИ-персонажи должны сохранять прежнее поведение, пока их автор явно не включит новое правило.

Новые правила выбора противника рассчитаны на сохранение одной цели на протяжении всей атаки по умолчанию (`PerAttack`). Авторы могут выбрать `UntilDefeated`, чтобы сохранять этого противника между атаками. Неизменённые ИИ-персонажи сохраняют прежнее поведение, включая защиту от смены цели, предоставляемую Legacy.

**В разработке: готовая к игре версия пока недоступна.**

## Настройка (предварительное описание)

Это поля AIC-конфигурации личности ИИ, а не новые элементы интерфейса. Примеры поясняют разрабатываемую конфигурацию; это не полные пакеты ИИ и не готовые к игре настройки. Имена параметров и их значения нужно писать точно как в примерах, независимо от языка интерфейса.

### Сохранить прежнее поведение

Для неизменённой личности не добавляйте новые поля. Значения по умолчанию: `RecruitPolicy: Native`, `AttackTargetPolicy: Inherit`, `AttackTargetCommitment: Default`. Набор войск и выбор противника включаются независимо.

### Выбрать противника

Предполагаемое назначение значений `AttackTargetPolicy`:

| Значение | Назначение |
| --- | --- |
| `Inherit` | Использовать исходный `TargetChoice` личности (по умолчанию). |
| `LowestPopulation` | Предпочитать противника с наименьшим числом мирных жителей. |
| `FewestTroops` | Предпочитать противника с наименьшим числом военных единиц. |
| `LowestCombatPower` | Предпочитать наименьшую оценочную военную силу, без учёта расстояния. |
| `Random` | Все допустимые противники имеют равный шанс; возможен повторный выбор. |
| `LastAggressor` | Реагировать на последний враждебный инцидент, отвечающий условиям, а не на каждый удар. |

`AttackTargetCommitment: Default` для новых правил означает `PerAttack`: выбрать цель при начале атаки и сохранять её до конца атаки. С `Inherit` сохраняется прежнее поведение Native/Legacy. Явно выберите `UntilDefeated`, чтобы удерживать допустимого противника между атаками. Если цель стала недопустимой, сначала нужно завершить текущую атаку; выступившая армия не должна менять противника посреди атаки.

Пример: случайный противник для каждой атаки, без смены в ходе атаки:

```json
{
  "AttackTargetPolicy": "Random",
  "AttackTargetCommitment": "Default"
}
```

### Распределить набор войск

`RecruitPolicy: WeightedRoles` распределяет решения о наборе между обороной, набегами, основной атакующей армией и вылазками. Вылазки — выход войск из замка для боя с ближайшими врагами. Прежние интервалы, списки войск и квоты сохраняются. Веса влияют на доступные варианты набора, но не гарантируют итоговое соотношение войск.

Задайте все три строки силы: `Default`, `Weak`, `Strong`. Четыре целочисленных веса каждой строки должны давать в сумме 100. Используются прежние `RecruitProbDef…`, `RecruitProbRaid…`, `RecruitProbAttack…`; `RecruitProbSortie…` добавляет вылазки и по умолчанию равен 0. Автоматического пересчёта нет. Пример, не рекомендация по балансу:

```json
{
  "RecruitPolicy": "WeightedRoles",
  "RecruitProbDefDefault": 30,
  "RecruitProbRaidDefault": 20,
  "RecruitProbAttackDefault": 40,
  "RecruitProbSortieDefault": 10,
  "RecruitProbDefWeak": 60,
  "RecruitProbRaidWeak": 10,
  "RecruitProbAttackWeak": 20,
  "RecruitProbSortieWeak": 10,
  "RecruitProbDefStrong": 20,
  "RecruitProbRaidStrong": 20,
  "RecruitProbAttackStrong": 50,
  "RecruitProbSortieStrong": 10
}
```

### Условный набор (расширенная настройка)

`RecruitConditions` по умолчанию — пустой список. Допускается до восьми правил по порядку. Каждому нужны `When` и четыре веса `Defense`, `Raid`, `Attack`, `Sortie` с суммой 100. Первое подходящее правило заменяет строку силы; если совпадений нет, используется эта строка.

В `When` поле `Strength` выбирает `Default`, `Weak` или `Strong`. Логические проверки: `HomeUnderThreat` (база под угрозой), `AttackActive` (идёт атака), `DefenseIncomplete` (оборона не укомплектована), `EquipmentSurplus` (избыток снаряжения). `true` требует наличия условия, `false` — отсутствия; пропущенная проверка игнорируется. Должны совпасть все указанные проверки; пустой `When` подходит всегда.

### Изменить или отменить настройки

Применяйте связанные поля вместе. Частичное обновление сохраняет пропущенные значения, включая ранее выбранный `UntilDefeated`. Для автоматического удержания цели задайте `Default`. Чтобы отключить эти правила:

```json
{
  "RecruitPolicy": "Native",
  "AttackTargetPolicy": "Inherit",
  "AttackTargetCommitment": "Default"
}
```

Переход только на `RecruitPolicy: Native` сохраняет прежние веса вылазок и правила неактивными. При `Native` не задавайте поля вылазок и правила. Вес вылазок 0 в `WeightedRoles` не возвращает набор Native.

**Ещё не завершены:** интеграция с игрой, точные определения угрозы, избытка снаряжения и подсчётов противника в исходной игре, пороги ответных действий, подготовка следующей волны, разделённые набеги и обязательные настройки Legacy. Готовой к выпуску инструкции для переключателей Legacy пока нет. Эти описания не подтверждают совместимость с сетевой игрой, сохранениями или повторами.
